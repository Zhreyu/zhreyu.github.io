Review 2 Pitch Script

Project: QUID + Agentic Retrieval Controller

Audience: Capstone review panel

Length: ~8–10 minutes talk + Q&A

0. Opening (30 sec)

Dense retrieval fails when short queries don’t match document vocabulary.
HyDE expands with autoregressive LLMs — but can hallucinate.
We built QUID: masked diffusion (LLaDA) for anchored query expansion.
After Review 1 you asked for an agentic angle — so we didn’t just expand prompts; we built an agent that calls expansion tools, critiques retrieval, and retries when confidence is weak.

1. Month 1 — Build + core claim (1–1.5 min)

What we did: Ported LLaDA-8B, wired QUID → BGE-M3 → BEIR.
Finding: QUID helps specialized domains (medical/finance vocabulary gap); SciFact often prefers HyDE/vanilla (knowledge/claim gap).
Takeaway: Diffusion expansion works — but not always. That motivates an agent.

Slide cue: domain table (NFCorpus/FiQA up, SciFact flat/down).

2. Month 2 — Full science (1–1.5 min)

Full baselines, ablations, mechanism analysis.
Semantic anchoring: QUID stays closer to the original query than HyDE (lower drift) while expanding vocabulary.
Paper draft ready. Core thesis locked: QUID is the expander; when it helps is query/domain dependent.

3. Month 3 — Polish (45 sec)

Paper revision, reproducibility, code release, presentation prep.
In parallel (Review 1 feedback): build the agentic controller on top of QUID — without replacing the diffusion contribution.

4. Agentic system — what we added (2 min)

Architecture

Query
  → PLAN tool ∈ {vanilla, QUID, HyDE}
  → EXPAND (tool call)
  → RETRIEVE
  → CRITIQUE (retrieval confidence)
  → if weak: RETRY different tool
  → ACCEPT best tried result

Important: QUID is still LLaDA masked diffusion. The agent does not replace diffusion — it decides whether and when to call it.

Tools

ToolRole
vanillaSkip expansion
quidDiffusion expansion (our method)
hydeHypothetical-document expansion
critiqueUnsupervised confidence check
retrySecond tool call if critique fails

5. Benchmarks — prove tool calls help (2–3 min) ⭐

We compare four policies on the same queries:

  1. always_vanilla — no expansion
  2. always_QUID — blind prompt expansion every time
  3. single-shot agent — one tool call
  4. multi-step agent — expand → critique → optional retry

SciFact (science claims, n=50) — main proof

MethodnDCG@10vs vanilla
always_vanilla0.6299—
always_QUID0.5999−3.0%
single-shot agent0.6280−0.2%
multi-step + tool calls0.6625+3.3%
oracle0.7004+7.1%

Say this clearly:

Blind QUID hurts on SciFact.
Single-shot routing almost recovers.
Multi-step tool calls beat vanilla by +3.3% and beat always-QUID by +6.3%.
When the agent retries, nDCG improves 67% of the time.
So this is not “better prompting” — tool-calling improves retrieval accuracy.

On medical text, the agent avoids over-expanding when confidence is already high — recovering accuracy vs always-expand.

Efficiency

Average expand tool calls ≈ 1.06 per query — we don’t spam tools; we retry only when critique fails (~6% of queries).

6. Closing thesis statement (30 sec)

Contribution 1: QUID — masked diffusion query expansion with semantic anchoring.
Contribution 2: An agentic retrieval controller whose tool calls measurably improve nDCG over always-expand and over single-shot routing.
Diffusion is the tool; agency is when and whether to use it.

Likely Q&A

Q: Isn’t this just HyDE with routing?

A: HyDE is one tool. Our expander is LLaDA diffusion (different generation dynamics + anchoring). The agent chooses among vanilla/QUID/HyDE and can retry after critique.

Q: Why doesn’t always-QUID win on NFCorpus here?

A: This Review-2 agentic bench uses 50 queries / 16 steps for cost. Full Month 1–2 BEIR (more queries, 32 steps) showed QUID gains on NFCorpus. The agentic result still shows routing beats blind expansion.

Q: How is critique not using labels?

A: Unsupervised: max cosine similarity to corpus + “did expansion hurt vs vanilla confidence?” No qrels at decision time.

Q: What’s next?

A: Learned router toward oracle; stronger HyDE backend when API available; step-budget as another tool argument.
